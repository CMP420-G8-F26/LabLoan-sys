1. Auditability: The system shall retain relevant loan, return, approval, and equipment-status information so that activities can be reviewed when required.
2. Privacy: The system shall restrict access to personal and loan information to authorized users according to their roles.
3. Error Handling: The system shall provide clear error messages when an operation fails or invalid information is entered.
4. Testability: Each major system module shall be testable independently and as part of the complete integrated system.
5. Version Control/Maintainability: The source code shall be maintained using version control, such as the team's GitHub repository, to support collaboration, change tracking, and recovery of previous versions.

2. Availability: The system should be available to authorized users during the laboratory's normal operating hours, excluding planned maintenance.
3. Security: The system shall require authentication before users can access protected system functions.
4. Validation: The system shall validate required input fields before storing user, equipment, loan, or return information.
5. Maintainability: The system shall be structured into modules so that individual components can be modified without unnecessarily affecting unrelated functionality.

Rachad Bouida Contributions
1.Authorization: The system shall enforce role-based access control so users cannot access functions outside their assigned permissions.
2.Data integrity: The system shall maintain accurate and consistent relationships between users, equipment, loan requests, loans, and returns.
3.Reliaility: The system shall prevent incomplete or invalid loan and return transactions from being stored as completed transactions.
4.Scalability: The system should be capable of supporting an increase in the number of users and equipment records without requiring a complete redesign.
